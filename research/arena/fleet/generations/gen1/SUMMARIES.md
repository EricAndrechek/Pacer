# Generation 1: what each agent did

One paragraph per agent, from its own hand-back notes. Scores are relative; absolute figures are left out because they come from one person's usage.

## g1-01-sonnet

Claude model `claude-sonnet-4-6`, effort low, niche machine-learning. Models: `g1-01-sonnet-bestcombo`, `g1-01-sonnet-calibrate123`, `g1-01-sonnet-calstack`, `g1-01-sonnet-combo123`, `g1-01-sonnet-cqr`, `g1-01-sonnet-router`, `g1-01-sonnet-stack123`

Built LightGBM quantile models with calibrated spreads plus calibration and stacking wrappers around the Timestral foundation models. The quantile-regression child (cqr) used about 70 engineered features with cross-fold spread scaling; in a one-episode test it cut five-hour CRPS by about a third versus the best foundation model, but its calibration broke on episodes with few past cycles, so a minimum-cycle rule and a physics-style fallback were added. calibrate123 shrinks the 123M Timestral's over-wide intervals by a CRPS-minimising scale found on its own backtests; it later became the best five-hour and seven-day model on the leaderboard tier in this generation. Other children were simplex stacks of two foundation models, a calibrated-plus-TimesFM stack, and a router sending five-hour and scoped targets to the quantile model and seven-day to the calibrated one. The agent noted that the 209M Timestral is badly calibrated on the five-hour meter and avoided it as a child. Git could not be used inside the sandbox, and some leaderboard calls were killed by the 10-minute Bash timeout, so only one calibration run had a result when the report was written. The agent judged its own work mostly from visible-tier tests and listed the remaining children as built but not yet scored.

## g1-02-haiku

Claude model `claude-haiku-4-5`, effort high, niche foundation-model. Models: `g1-02-haiku-fm-broad`, `g1-02-haiku-fm-clean`, `g1-02-haiku-fm-elite`, `g1-02-haiku-fm-ensemble`, `g1-02-haiku-fm-meter-stack`, `g1-02-haiku-fm-online`, `g1-02-haiku-fm-spend-ensemble`, `g1-02-haiku-fm-spend-stack`, `g1-02-haiku-fm-split`, `g1-02-haiku-fm-timestral-all`, `g1-02-haiku-hybrid-fm-struct`

Stayed in the foundation-model lane and built eleven ensembles of the pretrained forecasters (Timestral at several sizes, Chronos2, Moirai2, TimesFM) with equal-weight medians, CRPS-fitted simplex stacks, quantile pooling and an online exponentially weighted average. Some children combined direct meter forecasts with structural spend-to-meter models, and a few targeted spend, tokens and account split through the Timestral spend models. Most of the work was design: the sandbox blocked the arena-eval calls, so none of the models were scored during the run and the report states that plainly. The claimed insights (larger models are more accurate, ensembles beat singles, learned weights beat fixed ones) are the agent's expectations, not measured results from this run. It listed quantile-specific weights, horizon-dependent weights and regime-based selection as ideas it did not try. It judged the models as ready for evaluation but offered no evidence of how they rank.

## g1-03-sonnet

Claude model `claude-sonnet-4-6`, effort high, niche structural. Models: `g1-03-sonnet-hybrid`, `g1-03-sonnet-structural`

A structural, non-neural bootstrap for the five-hour meter: past cycles are weighted by similarity of level at the same phase, current burn rate, active-versus-idle state, time of day at cycle start and recency, then paths are sampled from those cycles' increments, started at the live value and kept monotone. On the visible tier it beat the spend-decay baseline by about 10%. Burn-rate conditioning helped most; using the live value as the conditioning level, strict activity matching, flat paths for idle accounts and day-of-week weighting all hurt. The hybrid child used the same bootstrap for five-hour and fell back to a Timestral structural child for weekly targets. The one completed leaderboard call showed the opposite bias to the visible tier (forecasts too low rather than too high), which the agent attributed to the hidden period being more active than the history the bootstrap sees. Two leaderboard calls were killed at the 10-minute timeout, and git writes were blocked in the sandbox, so everything was left uncommitted for collection.

## g1-04-opus

Claude model `claude-opus-4-6`, effort high, niche machine-learning. Models: `g1-04-opus-all`, `g1-04-opus-gbm-conformal`, `g1-04-opus-ml-spend`

A machine-learning niche with two LightGBM families. The spend and token model uses lag, rolling-window and calendar features, quantile levels with fatter upper tails and an AR(1) copula to correlate hours along a path; the meter model adds out-of-fold spread scaling and a minimum spread for weekly meters. Using separate context lengths for spend and tokens (longer for spend, shorter for tokens) and a minimum-spread rule for weekly meters gave modest gains of a few percent. Conformalized quantile regression, Student-t residuals, held-out calibration for spend and longer training leads were tried and discarded. The agent found that the weekly meter's outcomes are bimodal (keep rising versus reset), which a single unimodal quantile set cannot capture, and suggested a separate reset-probability model. Hidden-tier spend and token results were weaker than on the visible tier, and the meter model's leaderboard call was still pending at the end. Git writes and the arena-eval binary were intermittently blocked in the sandbox, and a meter call could take over half an hour.

## g1-05-opus

Claude model `claude-opus-5`, effort medium, niche ensemble. Models: `g1-05-opus-ens-all`, `g1-05-opus-ens-hourly`, `g1-05-opus-ens-meter`, `g1-05-opus-ens-meter-big`

Studied why the template combiners lost to their best child and built a banded ensemble: children chosen to disagree, simplex weights per forecast-lead band, a fitted spread factor, a deterministic mixture pool and a nowcast head that blends early path points toward the live meter. A mixture pool beat quantile averaging on all three meter targets, and adding two cheap children aimed at the five-hour window helped; several ideas did not, including a rise-shrink correction (which was its best idea on paper), Beta recalibration of the PIT and lead banding on its own. A hourly ensemble scored itself on the model's own turns. The wide version with the 123M Timestral timed out on the leaderboard scorer after about two hours, so the submission swapped in the 28M model and fewer backtest origins, and its own call had not returned when the run ended. Ablations on identical visible episodes showed roughly 5% and 8% lower CRPS than the best template combiner on the weekly meters and a several-fold better next-reading error, with a slight loss on five-hour that the final child set closed. The agent concluded that scorer time, not the loss function, limits how many children an ensemble can have.

## g1-07-sonnet

Claude model `claude-sonnet-5-5`, effort xhigh, niche statistical. Models: `g1-07-sonnet-analog-hourly`, `g1-07-sonnet-analog-meter`, `g1-07-sonnet-next-start`, `g1-07-sonnet-pool-five`, `g1-07-sonnet-pool-scoped`, `g1-07-sonnet-pool-seven`, `g1-07-sonnet-split-markov`

Used no neural nets or foundation models: an analog and block-bootstrap family built on the meter's cumulative points series, hazard-style next-start estimates, a two-state persistence chain for account split, and linear pools of the analog with the spend-decay models. The key lesson was that hyper-parameters tuned on the visible tier can hurt on the hidden one: per-block level noise helped visible weekly CRPS but badly over-dispersed the hidden weekly meters, so it was reverted. What carried over was self-calibration, a backtest on the model's own recent cycles that picks one multiplier or log-odds shift; it roughly halved the five-hour error and cut the next-start error by more than half, and the hourly model with a level feature improved by about a third between versions. The statistical models beat the foundation models on hourly spend, tokens, next-start and split, matched the spend-decay models at five-hour and did not beat them on weekly meters. A suite that combined many children timed out on the scorer (the machine was heavily loaded), and the agent found spend collapses when an account is pinned at a weekly cap. Git was read-only in the sandbox, foundation-model weights could not be fetched locally because of a TLS failure, and long waits were awkward under the 10-minute background-wait cap.

## g1-08-opus

Claude model `claude-opus-5-5`, effort high, niche foundation-model. Models: `g1-08-opus-fm`

Had the improved setup. Built one model for all seven targets: a zero-shot Timestral forecaster recalibrated on self-backtests of the same forecaster over the user's own past, conditioned on meter level, cycle phase and recent activity, with a prior map fitted on the visible tier and an explicit rationing step for users who stop just short of a weekly cap. Account split is a regime simulation (one account at a time, switching hazards, accounts blocked at their limits), next-start is an analog estimate, and spend uses the 28M model with a weekly-limit block that treats limit-held hours as missing. Paired many-cutoff harnesses gave far more statistical power than arena test, which flipped verdicts between seeds at about a dozen episodes. Calibration helped the weekly meters (mostly on error at reset and limit calls); averaged foundation-model ensembles, spend recalibration and blending with spend-decay did not help and were left off. Hidden-tier calls drew different episodes each time, so results swung widely, with weekly meters over-wide in one call and under-dispersed in another; spend remained too high relative to the hidden period. The agent regarded it as a reasonable compromise rather than a clean win.

## g1-09-opus

Claude model `claude-opus-5-5`, effort xhigh, niche ensemble. Models: `g1-09-opus-analog-spend`, `g1-09-opus-ensemble`, `g1-09-opus-nextstart`, `g1-09-opus-split`, `g1-09-opus-struct-analog`

Had the improved setup. Built a routed in-process ensemble: per target a recipe pools the 123M Timestral meter, a structural model driven by the agent's analog spend forecasts, and a spend-decay model, with Vincentization and a spread factor. A weekly re-base overlay notices that weekly allowances are sometimes reset mid-cycle under an unchanged reset time and re-bases a share of paths accordingly; those cells otherwise dominate visible-tier CRPS. Child-worker ensembles timed out on the scorer because each child is re-spawned and re-fitted at every checkpoint, so everything was moved in-process, which fixed it. Fitted stacking weights, within-episode EWA and as-of adaptation all failed out of sample, and equal weights over a greedy set won; no static recalibration transferred because the visible tier wanted higher forecasts than the hidden one. Hidden calls drew different episodes, so scoring was noisy, but the final version showed a better next-start and scoped result than earlier ones and showed scoped over-forecast and weekly meters over-dispersed throughout. The agent also reported that the Toto backend could not run in the template because a vendored data package was missing.

## g1-10-fable

Claude model `claude-fable-5-1`, effort high, niche statistical. Models: `g1-10-fable-analog`, `g1-10-fable-mix`

Had the improved setup. One idea across all seven targets: kernel-weighted analog ensembles drawn from the account's own past, with no pretrained weights. Five-hour and scoped meters use cut-cycle analogs; the seven-day meter uses a day-activity model (active or idle days from a two-state chain, with day totals drawn from the account's own days and a prior); hourly targets use analog hour-starts; next-start is a discrete-time hazard. A first weekly block bootstrap collapsed to a flat line on a quiet account just before it became active, and the day model with shrinkage priors fixed it. On the hidden tier the hourly targets, split and next-start beat the earlier references, the five-hour meter matched the best in one call, and weekly and scoped meters stayed behind the leaders. A five-hour shrink tuned on one call over-corrected on the next, so the final setting was a compromise; call-to-call spread was large enough that no single call should decide anything. A mixed model with children ran past the shell's one-hour limit and its result was lost, though the call was charged. The agent suggested averaging several eval calls per candidate and proposed an eval-last helper and a way to build history views for debugging.
