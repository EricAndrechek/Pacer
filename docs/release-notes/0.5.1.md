Pacer can now tell an AI agent how much budget it has left — and the agent can act on it.

## Heads up if you scrape `/metrics`

`pacer_rate_limit_*` now carries an `account` label. On a machine with one
account nothing changes. With two signed in, a query like
`pacer_rate_limit_used_ratio{window="five_hour"}` returns **one series per
account** instead of one — so a single-stat panel or an alert rule that assumed
a single value needs an `account="…"` matcher or an aggregation like `max()`.

That's the only breaking change here, and it's deliberate: the alternative was a
second metric family meaning the same thing.

## A pacing skill, shipped in the app

Pacer includes a Claude Code skill. Install it from **Settings → Integrations**
and Claude can read your usage before it starts a long run or fans out a pile of
subagents, pause and checkpoint when a window is nearly full, and wait out the
reset instead of losing the work. One shared read serves a whole fan-out, so a
hundred subagents cost Pacer nothing.

It needs no dependencies beyond what macOS already has, and it updates when
Pacer updates — there's nothing to re-download.

Three things it does that matter in practice:

- **A per-model cap only stops work that uses that model.** A full Fable weekly
  window has nothing to say to an agent running Opus, and won't stop it.
- **It knows which account you're on.** With two logins signed in, it reads the
  one this session is actually billing — not whichever was picked last.
- **It can gate on the forecast, not just the level.** "Will this finish before
  I run out" is a better question than "am I nearly out", and it asks that one.

One optional line in your `CLAUDE.md` makes pacing the default for long runs.
Because that line points at a file Pacer owns, it never needs re-pasting.

## Every window, every account, over HTTP

The local API used to report exactly two rate-limit windows for one account.
Pacer has tracked more than that for a while — per-model caps, and every account
you're signed into — and now the API does too:

- `/v1/snapshot` reports every window, including per-model caps, and `?account=`
  scopes the whole payload to one login.
- `/v1/limits/history` gives each window's utilisation over time, so you can
  chart or fit it yourself.
- `/v1/session` and `/v1/sessions` report what a session is running and where
  your other live sessions are.
- Each window now carries how fast it's climbing — measured over the last half
  hour as well as the engine's smoothed average. When those two disagree,
  you're in a burst.

## Your plan, precisely

Pacer now shows **Max 20×** rather than just "Max", on the dashboard, in
Settings, and over the API. It's the number that gives a percentage meaning: 20%
of a Max 20× budget is four times 20% of a Max 5× one.

## Fixes

- Switching accounts now takes effect immediately. Pacer could spend up to half
  an hour still polling the account you'd just left.
- An account's details no longer get stuck at whatever was first recorded for
  it, which is why plan information could never appear.
