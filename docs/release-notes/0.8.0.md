Costs use the rates in effect when you made each request, forecasts show a live estimate between readings, and Ultra and Claude Desktop accounts are tracked properly.

## Costs and pricing

### Costs use the rate in effect when you made the request
Each request is priced from a dated price history, so a later price change no longer rewrites what you already spent. Long prompts are priced at their own tier, and 1-hour cache writes, fast mode and US-only routing are priced too. Fast mode and multi-call responses are counted call by call.

### Cost by part, and sortable tables
Costs split into input, output, cache reads and cache writes, shown in the daily chart, the Day, Project and History breakdowns, and a Mix bar per model. Tables default to tokens, cache hit rate, output share, cost and mix. Right-click to show, hide, reorder or resize columns.

## Forecasts and the live meter

### A live estimate between readings
Between Anthropic's readings, the menu bar, dashboard and widgets show the last reading plus the API spend since. An estimate has a decimal (42.6%), a reading doesn't (42%). An estimate is never saved as a reading and never goes below one.

### Forecast lines and claims
Forecast lines stay up between polls, including on accounts that are read in bursts. An idle window says "holds until reset" or "≈X% at reset" instead of nothing. A red "limit in…" now needs at least half the window used and the crossing to hold across two updates; otherwise it reads "may hit limit in…".

### Forecasts pick the method that fits you best
Pacer scores its forecast methods on your own history in the background, capped at about a fifth of one CPU core, and uses the one with the best record, falling back to the previous rule. Two networks ship in the app, which adds about 130 MB; others download once on first use.

### Pacing uses the live estimate
`pacer gate`, `status` and `wait` judge the live estimate rather than the last poll, padded for how old the reading is, so they pause closer to the limit. `pacer report` shows both: `42.6% est · read 42%`.

## Accounts and plans

### Ultra accounts
Anthropic renamed Max 20× to Ultra and Max 5× to Max. Verified Ultra accounts have no 5-hour limit now, so Pacer hides their 5-hour window instead of showing an old reading, and the menu bar and widgets show the 7-day figure.

### Claude Desktop
Cowork (agent-mode) sessions count under a "Claude Desktop (agent)" project, and each Desktop install counts with its own sessions. An account Claude Desktop is using, but Claude Code isn't, gets a "Desktop" chip for 30 minutes after its last activity. An idle account whose login has expired says "auth paused".

## Alerts

### One alert per window per account
Alerts show while Pacer is the app in front. Each window of each account has one alert, which the next one replaces, and it clears when the window resets. Alerts have Mute until reset and Open Pacer buttons. Settings → Notifications can alert from live estimates too.

## Privacy

### Crash reports and usage stats
Pacer now sends crash reports and anonymous usage stats to Sentry so bugs and slowdowns get found. Turn either off in Settings → Privacy.

## Fixes

### Lower memory in long sessions
Memory settles at a few hundred megabytes instead of climbing past a gigabyte during long runs.

### Tokens, subprojects and ranges
Tokens now means every kind of token in one total, and Top Days ranks by it. Subprojects group by folder inside a repo, "last N days" covers exactly N calendar days, and the low cache hit hint fires below 90%.

### Profiles and the pace card
A Claude Code profile created while Pacer runs is counted within a minute. Pace-card hovers and open popovers survive a window or account appearing.

**Your data is untouched.** Pacer rebuilds cost history in the background on first launch. After that, an older version of Pacer can't open your data, so this one can't be downgraded.
