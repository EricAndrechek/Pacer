Two fixes to `pacer wait`, the command the pacing skill uses to sit out a limit.

## `wait` keeps the rules that paused it

The skill's routine is to check (`pacer gate`) and, if told to pause, run `pacer wait`. A pause because a window was *projected* to fill within your horizon (`--eta`), or because it passed a limit you set yourself (`--cap`), was followed by a `wait` that judged only the default limit, so it resumed at once and the run went straight back into the pause. `wait` now uses the same `--cap`, `--eta`, `--model` and `--window` as the check that paused, unless you give it your own, and says which it took.

## `wait` notices an account switch in about a second

`wait` checked Pacer every 15 seconds. It now listens for Pacer's news and looks the moment something changes, so switching to an account with room resumes your run in about a second. With Pacer's local API off it checks on the same 15-second interval as before.

**Your data is untouched.** No reset, no re-import.
