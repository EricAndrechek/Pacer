Freeze reports that say what the Mac was doing, a track record that ignores the moments Pacer wasn't reading, and updates that now come from Pacer's own site.

## Freeze reports
When Pacer freezes and none of Pacer's own code is involved, the report used to land in one catch-all. Reports are now grouped by what the Mac was doing at the time, such as laying out a window, drawing to a display or waiting on a system lock, so each cause can be found and fixed on its own.

## Smoother
Checking your accounts' usage now saves what it reads away from the main thread, so the window stalls less on a busy Mac.

## Forecast accuracy
Pacer's track record, and the calibrated ranges built from it, no longer count moments when it wasn't reading, such as while the Mac was asleep or Pacer was closed. Those gaps used to skew the score. Pacer re-grades its forecast history once, at first launch. It takes a few seconds.

## Updates from Pacer's own site
Updates and price data now come from pacer.andrechek.com instead of GitHub Pages. Older versions keep working, and still get this update from the old address. The share card shows the new address.

## Privacy
Freeze reports (sent only while crash reports are on in Settings → Privacy) now include the names of macOS's own system functions, only Apple's code, never yours and never file paths. That is a new kind of data in a report, and it lets us tell one cause of a freeze from another. Pacer still never sends prompts, projects, files, accounts or costs.

**Your data is untouched.**
