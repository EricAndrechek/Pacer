A steadier dashboard, a window and menu-bar item that stay where you put them, and usage that lands on the account you're actually signed in with.

## The dashboard stops jumping

Cards no longer shift around while Pacer loads or updates. Each of these moved everything below it:

- **Switching the active login** (with `claude-swap`, or after signing in again) blanked the rate-limit pace card to "Loading history…" and back, even on "All accounts". It now stays put.
- **At launch**, the charts arrive into space already kept for them instead of pushing the page down by half a screen.
- **As forecasts come in**, the forecast line, the chips, Today's badge and the month-end bar keep their space while they wait.
- **While idle**, the "resets in…" caption no longer re-wraps as time passes.

Switching tabs is quicker too. Projects opens in under half the time on a large history, and the toolbar no longer flashes empty for a frame on every switch.

## The window stays where you keep it

When your monitors went to sleep, macOS could move the dashboard before telling Pacer the displays had changed, and Pacer remembered that move as the window's home. It then reopened somewhere you couldn't see it. Moves that coincide with a display change are no longer saved.

## The menu-bar item keeps its place

Pacer's menu-bar item now has a stable identity, so macOS remembers where you dragged it across launches and updates. The first time this version runs it may appear in the default spot. Drag it back once, and it stays there from then on.

**Activity rings are the default menu-bar icon.** If you never picked an icon style, you'll see the rings now. The old icon is still in Settings → Menu Bar.

## Usage goes to the account you're signed in with

If you use more than one Claude login, Pacer could file turns and rate-limit readings under whichever account `~/.claude.json` last named. That file can lag behind a switch while Claude Code is already using the other login's credentials. Pacer now goes by the credential Claude Code is actually using. From this version on, new usage lands on the right account. History recorded under the wrong one before the update isn't moved automatically.
