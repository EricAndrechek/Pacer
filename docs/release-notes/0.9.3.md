Burn rates that stop spiking after a gap, a dashboard that does less work while your displays sleep, and updates that can't get stuck waiting to install.

## Rate limits after a gap
If Pacer hasn't been reading for a while, because a login lapsed, the Mac was asleep or Pacer was closed, it no longer reports a false burn-rate spike from the first few readings. Rates, and the `pacer gate` check that uses them, now wait for real readings to measure from.

## Less work while you're away
While every display is asleep, the dashboard holds off its redraws and catches up the moment a screen wakes. Nothing you can see goes stale: the menu bar, widgets, notifications, the local API and the `pacer` command keep updating as before.

## Updates that can't get stuck
- A downloaded update no longer waits forever for a quiet moment. An idle Pacer that's left frontmost, or a Settings window left open, no longer holds it back. An update held for more than 72 hours installs as soon as nobody is at the Mac.
- Installs never interrupt text you're typing.

## Smoother
- Quitting no longer hangs. A bug from 0.9.2 could stall Pacer on the way out.
- Checking your accounts' usage does less on the main thread, so the window stays responsive while it polls.
- A login that Anthropic keeps refusing (HTTP 403) is parked for six hours, and Settings marks it "refused", instead of being retried constantly. Nothing is removed, and a token you change is tried straight away.

## A daily accuracy check, extended
Once a day, Pacer now checks every request Claude Code answered against its own records, not just the totals. In the field, Pacer missed nothing. The gap that looked like under-counting came from Claude Code counting some calls it never writes to a transcript, such as "while you were away" recaps and conversation compactions. The check now allows for those.

## Freeze reports
Freeze reports now say how busy the Mac was, its load, memory pressure and so on, so a slow Mac can be told apart from a slow Pacer.

## The `pacer` command
Inside a Claude Code session, `pacer` now just says go or pause, and what ends the pause, instead of handing agents usage percentages to plan with. To see the numbers, set `PACER_PACING=informed` for a session or a repo, or run `pacer mode informed`. With an account switcher, a pause says when a switch is expected, and `pacer wait` waits for it. In `pacer json`, `otherAccounts.withRoom` now means accounts with real room to resume onto.

## Privacy
No new kinds of data about you are sent. Pacer never sends prompts, projects, files, accounts or costs.

**Your data is untouched.**
